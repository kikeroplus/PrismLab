# PrismLab 仕様

PromptWordCrafter・ImageMimicArt・J-Rate の「作る」部分をまとめる生成アプリです。企画の経緯と画面の見本は企画書 (claude.ai の PrismLab 企画) にあります。

- 生成の決まりは J-Rate の `docs\generation-standard.md` に合わせる。ワークフローの作り方 (プロンプト・リファレンス画像・ラストフレーム・長さなどの印) は J-Rate の `docs\workflow-guide.md`。生成・読み取り・盛る・差し込みは `..\GenCommon\gencommon` をそのまま使う。
- 見る・評価する・整理するのは J-Rate。PrismLab とのやりとりは、出力フォルダとファイルの★ (System.Rating) と、J-Rate・PromptWordCrafter の右クリックの「PrismLab に送る」(5 章)。
- 画面は「量産ライン」と「物語」の 2 つ。T2I / I2I / I2V はモードとして選ばず、ワークフローと元画像から自動で決まる。

## 1. 機能を足すときの基準

新しい機能は、作る前に次のどこに入るかを決める。どこにも入らないものは作らない (ComfyUI のワークフロー側でできないか先に考える)。

| 入れる先 | 中身 |
|---|---|
| 量産ラインのステップ | フォルダ全体に同じことをする。人の手を待たない |
| 物語のシーン | 1 つを見て直して選ぶ |
| GenCommon | 両方で使う (1 か所直せば両方に効く) |
| J-Rate | 見る・比べる・評価する・整理する |

## 2. 見た目

- 暗い配色 (ImageMimicArt と同じ。ui-standard 14 章)。
- **ワークフローの種類の色は、今の色分けを引き継ぐ** (`gencommon.set_cards.KIND_COLORS`): T2I 青・I2I 緑・I2I CN 紫・T2V 橙・I2V 赤紫。札の文字も同じ (`T2I` / `I2I` / `I2I CN` / `T2V` / `I2V`)。Depth などで構図を写す I2I は「I2I CN」(ControlNet を使う I2I) として紫になる。見分け方も今と同じ (`comfy.workflow_kind` と `comfy.uses_controlnet`)。
- LLM を使うステップ (読み取り・盛る) は、図の画面の LM Studio の薄紫 (`#a9a2ed`) で縁取る。
- 状態は文字より絵で見せる: ステップごとに出来たもののサムネール、進み具合の棒。失敗したものは赤い枠。
  - サムネールは画像なら自分で読み、読めないもの・動画は Windows のサムネールを使う。Windows には**本物のサムネールだけ**を頼み、作れないときに関連付けアプリのアイコンを返させない。読めなかったものは覚えずに、少し待って読み直す (1.5・3・6・12・24 秒後。だめなら読めないものとして覚える)。2026-11-18 利用者の指摘: ネットワークの出力フォルダで、出来たばかりのファイルが一瞬読めず、アプリのアイコン (画像と星) が結果のサムネールに残っていた。
  - 動画のサムネールは、いつもの絵 (Windows のサムネール、始めのほう) のまま、右下に**最後のコマを小さく重ねる** (黒い縁と白い細線。2026-11-15 利用者の希望)。最後のコマは裏で OpenCV で読む (終わりの少し手前から終わりまで読んで最後に読めたもの。読み終えたらすぐ閉じる)。
- 設定はステップの中に閉じる: ステップをクリックしたときだけ、そのステップの設定を開く。

## 3. 量産ライン

### レシピ

- 入口 (フォルダと★の絞り込み) と、左から右へ並べたステップでできている。並んだ囲みの呼び名は「ステップ」(「ノード」は ComfyUI のノードと紛れるので使わない)。よく使うつなぎ方をレシピとして保存し、上の札で切り替える。
- ステップの並びの欄は、いちばん高い札 (入口の★の内訳などで伸びる) が全部見える高さにし、縦のスクロールバーは出さない。そのぶん結果の欄を下へ送る (2026-11-18 利用者の希望)。高さは 262〜520px で、窓の高さの半分まで。
- ステップの直し方: クリックで設定。「＋ ステップ」で末尾に足す。ステップのあいだの → (乗せると「＋」) を押すと、種類を選んでそこに挿入する。右クリックで 設定... / 種類を変える ▸ / 左に挿入 ▸ / 右に挿入 ▸ / 複製 / ◀ 左へ / 右へ ▶ / このステップを削除。足す・挿入・種類を変えるときは、その種類の設定の窓で OK したときだけ入る。量産が動いているあいだは、**そのレシピだけ**直せない (始めたときの写しと進み具合を見せる)。ほかのレシピは量産中も切り替えて直せる (2026-11-17 利用者の希望。ステップ・入口・出力・送られたもの・レシピを足す・名前を変える・並べ替え。動いている量産のレシピは消せない)。レシピの札には、動いている量産のものに「▶」を付ける。量産は一度に 1 つなので、ほかのレシピの「開始」「1 枚で試す」は量産が終わってから。
- **コピー・貼り付け** (2026-11-18 利用者の希望): ステップの右クリックの「コピー」「ここから右をまとめてコピー」で覚え、ほかのレシピでも 右クリックの「左に貼り付け」「右に貼り付け」、→ の挿入と「＋ ステップ」のメニューの先頭の「貼り付け: (種類)」で入れる。中身はコピーしたときのまま (窓は出さない)。何度でも貼れる。覚えるのはアプリを閉じるまで。動いている量産のレシピからもコピーはできる (右クリックはコピーだけ)。
- **バイパス**: ステップ右上の ↷ (右クリックの「バイパス」も同じ) で入れる・切る。バイパスのステップは飛ばして、前のものをそのまま次に渡す (設定は残る)。見た目は点線の灰色の縁・取り消し線・「バイパス」の札・「そのまま通す」。
  - 入れられるのは、入れてもラインに新しい問題が出ないステップだけ (スイッチもそのステップにだけ出す)。問題とは「生成のステップが 1 つも動かない」と「盛るの前に読み取りがない (直前の生成よりあと)」。例: 読み取り → 盛る → 生成 では、盛るは入れられるが、読み取りと生成は入れられない (盛るを入れれば、読み取りも入れられる)。
  - バイパスのステップは、始めるときに中身 (プリセット・ワークフロー) を確かめない。すべてバイパスなら始めない。
- ステップは 12 種類: **読み取り** (読み取りプリセット・読み取り済みでも読み直す)、**盛る** (エンハンサー)、**英語に**、**追加テキスト** (足す文)、**差し込み** (フォルダ)、**置き換え** (決まり)、**覚える**・**思い出す** (メモの名前)、**増やす** (分ける数)、**★を待つ** (★の数)、**最後のコマ**、**生成** (ワークフロー・長さ・ベースプロンプトを付けるか)。
- **追加テキスト・差し込み** (文を足すステップ。色は文字の色):
  - 追加テキスト: 入力した文を、どの画像にも同じに足す。
  - 差し込み: フォルダの `.txt` を名前順 (自然順) に 1 枚ごとに 1 つずつ足す。一周したら最初へ。空のファイルは飛ばす。どこまで使ったかは GenCommon の差し込みと同じ `insert_positions.txt` (3 アプリと共有)。設定の窓に「次: 003.txt (3 / 20)」と「最初から使う」。
  - 盛る前か盛ったあとかは**置いた位置で決まる** (GenCommon の枠の「盛る前に入れる」のかわり): 盛るより前なら、読み取った文のあとに改行でつないで一緒に盛る。盛ったあとなら、盛った文のあとに改行でつないでそのまま付ける (セリフを一字一句守るならこちら)。最後にベースプロンプト。
  - 差し込みのファイルは「開始」したときに 1 枚ごとに割り当て、そのとき位置を書く (続きから始めても変わらない)。「1 枚で試す」では次のファイルを使うが、位置は進めない。
  - 記録 (generation-standard の `inserts`) には `slot: -1` で残す (J-Rate の「この設定で生成する」は枠として使わない)。読み取った文も足した文もないまま生成に来たら、ワークフローのプロンプトのまま。
- 生成のステップはいくつでもつなげる。生成のステップで出来たファイルが、次のステップの元になる (「実写 → I2I CN → 読み取り → 盛る → I2V」)。出来たファイルが複数 (画像が何枚も出る I2I) のときは、次のステップには 1 つ目を渡す。
- 生成のステップを通ったら、プロンプト (読み取った文・盛った文・足した文) は空に戻す (新しいファイルには新しい説明が要るので)。プロンプトが空のまま生成のステップに来たら、ワークフローに書かれたプロンプトのまま送る。
- **覚える・思い出す** (2026-11-18 利用者の希望。生成を通ると文が空に戻るので、T2I に送った文を次の I2V でも使う、などのため。色は文字の色、札は「メモ」):
  - 覚える: その時点のプロンプトを**状態まるごと** (元の文・盛った文・足した文。盛る前 / あとの区別も) 名前のメモに覚える。メモは件ごとに持ち、生成を通っても消えない (`line_run.json` の件の `memos` に残すので、続きから始めても使える)。
  - 思い出す: 同じ名前のメモから戻す。設定の「今の文を置き換える」(既定) なら覚えた状態にそっくり戻す。外すと**後ろに足す**: 今の状態で送るはずの文 (読み取った説明など) のあとに、メモの状態で送るはずの文をつなげて、それを元の文にする (あとに「盛る」を置けば一緒に盛る)。今の文がなければ置き換えると同じ。
  - メモは名前で何個でも持てる (既定は「メモ 1」。設定の窓で、このレシピの「覚える」の名前から選ぶか、新しく書く)。
  - 例: 入口 (テキスト) → 盛る → 覚える → 生成 (T2I) → 思い出す → 生成 (I2V)。I2V にも T2I と同じ盛った文が送られる。
  - その位置で文がない「覚える」(「覚える文がありません」) と、前に同じ名前の「覚える」がない「思い出す」(「このメモを覚えていません」) は赤い縁で理由を出す。後者は開始・試作も理由を出して始めない。あとで思い出すメモの「覚える」はバイパスにできない。
- **英語に** (2026-11-18 利用者の希望): いまのプロンプト (元の文・盛った文・足した文) のうち、ASCII 以外の文字 (日本語など) が入っている文だけを LLM で英語に訳す (文ごとに 1 回ずつ。英語だけの文は送らない)。同じ文は 1 回の量産のあいだ覚えておき、もう訳さない。サーバー・モデルはエンハンサーと同じもの (始めたときに写す)。(word:1.2)・<lora:...>・固有名詞は残すよう頼む。文がない位置に置くと赤。
- **最後のコマ・増やす・★を待つ・置き換え・ワイルドカード** (2026-11-18 利用者の希望。提案した 5 つを全部):
  - **最後のコマ**: 前の生成で出来た動画の最後のコマ (`story.save_frame`、物語と同じ取り出し方) を `(出力フォルダ)\コマ\(動画の名前)_last.png` に書き、次のステップにはその画像を渡す。結果の一覧には出さない。動画でなければその件は失敗。画像の生成のあとに置くと赤 (「動画がまだありません」)。例: I2V → 最後のコマ → I2V で続きの動画。
  - **増やす**: その件を N 本 (2〜20) に分け、そこから先をそれぞれ通す。ここまでの文・メモ・いまのファイルは写し、ここまでに出来た結果は元の件にだけ残す。分けたものは元の件のすぐあとに並べる (`Item.branch` = 枝の番号)。あとの盛るは 1 本ごとに盛り直し、差し込みは 1 本ごとに次のファイル (始めるときに 件の数 × 枝の数 だけ割り当てる。枝 k の鍵は `"ステップ/k"`)、ワイルドカードも 1 本ごとに選ぶ。件の数は量産の途中で増える。
  - **★を待つ**: いまのファイルの★ (J-Rate で付けたもの) が設定の数以上なら通し、なければ「★待ち」(`GATED`) で止める。★待ちがあるあいだ量産は終わらない (台は使わない)。★は PrismLab に戻ったとき・1 分ごと・「★を読み直す」で裏で読み直し、付いたものを先へ。「★待ちを終える...」で残りを「★なし」(`SKIPPED`) で終える (ここまでに出来たものは残し、元の★も引き継ぐ)。中止すると★待ちも取り消す。試作 (1 枚で試す) では止めない。テキストの入口で生成より前に置くと赤 (テキストには★がない)。ステップの札に「★待ち n」「★なし n」、まとめにも出す。
  - **置き換え**: 1 行に「元 => 先」(「→」も可)。先がない行・区切りのない行は元を消す。# の行は飛ばす。大文字・小文字は区別しない。いまのプロンプト (元の文・盛った文・足した文) のすべてに使い、消したあとに残る「, ,」・行の頭と終わりの「,」・続いた空白は詰める。決まりが空なら始めない。文がない位置に置くと赤。
  - **ワイルドカード**: 追加テキストに `{a|b|c}` と書くと、1 件ごとに 1 つ選ぶ (入れ子は内側から。| のない `{…}` はそのまま)。選んだ文を記録 (足した文) に残す。差し込みのファイルの中身には使わない。
- 中身は値で覚える (ワークフローはパス)。読み取りプリセットとエンハンサーは名前で覚える (generation-standard 2 章と同じ)。
- 初めて起動したときは「★から動画」「実写クローン」「クローン → 動画」の 3 つを入れておく (ワークフローは未設定)。
- 置き場所: `%APPDATA%\PrismLab\recipes.json`。

### 入口

- 入口の種類を上の **[フォルダ] [1 枚] [テキスト]** で切り替える (レシピごとに覚える)。
- **回数** (どの入口でも。1〜999): 同じ元を何回通すか。並びは「全部の元を 1 回ずつ → 2 回目 …」(途中で止めても、どの元も 1 本は出来ているように)。1 回が 1 件。入口の札に「対象 n 枚 × m 回」。
- **テキスト** (T2I の量産): フォルダの直下の `.txt` (自然順、中身が空のものは除く) を 1 つ 1 件にし、中身を元の文にする (読み取った文と同じ扱いで、盛る・生成に渡す)。入口の札は文字の色で、先頭のファイルの文を出す。
  - 元画像がないので、画像の要るステップ (読み取り・I2I・I2V の生成) は、最初の生成 (T2I / T2V) より前に置けない。置いたステップは赤い縁と「⚠ 画像がまだありません」を出し、開始・試作は理由を出して始めない。バイパスもこれを守る。
  - 出来たファイルの名前は `(テキストの名前)_t2i.png`。★の引き継ぎはしない (テキストに★はない)。「1 枚で試す」は先頭か、ドラッグした `.txt`。
- **1 枚** (LoadImage のように): フォルダのかわりに 1 枚の画像から始め、**回数**ぶん同じ画像を通す (1〜999 回、1 回が 1 件)。差し込みは 1 件ごとに次のファイル、盛るも 1 件ごとなので、1 本ずつ違うものが出来る。
  - 入口をクリック (ファイルを選ぶ) か、画像をドラッグして選ぶ。★の絞り込み・内訳・「J-Rate で★を付ける」は出さない。入口の札に「画像: 名前」と「n 回通す」。
  - 出力の既定は `(画像のあるフォルダ)\(レシピ名)`。同じ名前は ` (2)` を付ける (上書きしない)。
  - 「1 枚で試す」はその画像を 1 回だけ。途中のステップで画像を差し替える・生成に 2 枚目として渡すのは、今はしない。
- **フォルダ**: フォルダの直下の画像 (`.png .jpg .jpeg .jpe .webp .bmp`)。名前順 (自然順)。
- ★の絞り込み: なし / ★1 以上 〜 ★5。★はファイルの System.Rating (J-Rate と同じ: 1 / 25 / 50 / 75 / 99) を読む。
- 入口のステップに、対象の枚数と先頭の 3 枚、★の内訳 (★5 3 · ★4 12 · なし 40。ある★だけ) を出す。
- **J-Rate で★を付ける**: 入口のステップのボタンで、入口のフォルダを開いた J-Rate を起動する。★を付ける・見る画面は PrismLab には作らない (見る・評価するのは J-Rate)。
  - ★はファイル自身に書かれるので、受け渡しの仕組みは持たない。PrismLab に戻ったとき (1 秒以上ほかのウィンドウにいたあと、ウィンドウが前に来たとき) に★を読み直し、対象の枚数・内訳・先頭の 3 枚を描き直す。量産が動いているあいだは読み直さない (始めたときの入口で続ける)。
  - J-Rate は 2 重起動を止めていないので、押すたびに新しい J-Rate が開く。

### 出力

- 出力フォルダは、レシピで決めたフォルダ。空なら `(入口のフォルダ)\(レシピ名)`。
- **元の★を引き継ぐ** (出力の行のチェック。レシピごと、既定はオン。generation-standard 6 章のオプション): 1 件が終わった時点の元の★ (生成中に J-Rate で付けたものも) を、その件で出来たファイルすべて (途中のステップのものも) に書く。更新日時は変えない。書けない形式・使用中は少し待って 3 回試し、だめなら付けない。★のない元・失敗・取り消しの件は何もしない。
- 名前は `(元の名前)_(印).(拡張子)`。印は動画なら `video`、画像はワークフローの種類で `t2i` / `i2i` / `cn`。つないだステップでは続けて付く (`photo_cn_video.mp4`)。同じ名前があれば ` (2)` を付ける (上書きしない)。
- 生成の記録は今のアプリと同じ形で `%APPDATA%\PrismLab\comfy_history.txt` に残す。
- 読み取った説明は、読み取ったファイルと同じ名前の `.txt` に書く (generation-standard 6 章)。

### 振り分け (台)

- ComfyUI を最大 3 台まで使う。台は登録してある接続先から選ぶ (「台の設定...」)。役割は決めず、空いた台に何でも回す。
- 1 台に同時に 2 件まで送る (generation-standard 6 章)。終わった台から次の 1 件を取る。
- **台は量産ラインと物語 (候補づくり・バッチ) で共通**。台の空きを分け合い、1 台に送るのは両方を合わせて 2 件まで (`engine.POOL`)。両方が台を待っているときは**物語が先**: 物語に生成を待っている件があるあいだは、量産ラインはその件数ぶんの空きを残す (動いているものを追い出しはしない)。空きのある台のうち、**使っている数の少ない台へ先に回す** (2 台あるのに 1 台に 2 件たまり、もう 1 台が遊ばないように。頼み済みでその台の続きを待つ件は除く)。台の設定・見張り (繋がらない台・続けて失敗した台) は量産ラインと物語でそれぞれ持つ。2026-11-17 利用者の決定 (台をレシピ・物語ごとに決めるより、空いた台を自動で分け合う。物語のバッチは 1 件ずつ順に進むので、待たせると全体が止まるため物語を先に)。物語のタブの上の「台: FALCON · CONDOR」も同じ「台の設定...」を開く。

### 候補

- ワークフロー (登録したもの。種類を添えて)・長さ・ベースプロンプト・候補の数 (1〜9、既定 3) を決めて「候補を作る」。シーンのフォルダに出来る。量産ラインとは別に動き (量産ラインと同時に動いてよい。台の空きは分け合い、物語が先。3 章「振り分け」)、一度に 1 つのシーンだけ。作っているあいだは「中止」。
- 候補を選ぶと、上に **元画像 | 候補 (始め) | 候補の最後のコマ** を並べて出す (画像の候補なら 元画像 | 候補)。最後のコマはステップのサムネールと同じく裏で読む。消すときは、その候補のサムネールを読んでいる途中なら読み終わるのを待ってから (最大 3 秒) ごみ箱へ送る。
- 候補は新しい順。選ぶと上に大きく出し、ダブルクリックで再生 (画像は関連付けアプリ)。Ctrl / Shift で複数選べる。右クリック: 再生 / フォルダを開く / このときのプロンプトに戻す / 候補から外す (ファイルは残す) / 削除 (ごみ箱へ)。
- **候補ごとの記録** (2026-11-15 利用者の希望。あとで途中から直せるように): 候補ごとに、作ったときの **元のプロンプト**・**盛ったあとのプロンプト (送った文)**・**リファレンス画像** を `story.json` に残す。候補に指を置くと出す。「このときのプロンプトに戻す」で、元のプロンプトと盛ったあとのプロンプトの両方の欄に戻す (今の文は履歴に残し、Ctrl+Z でも戻せる)。シーン自身の元のプロンプト・盛ったあとのプロンプトも、直すたびに `story.json` に書く。
- **候補の削除** (Del / 右クリック。ui-standard 7 章と同じ): ファイルをごみ箱へ送る。1 つなら確かめず、複数のとき・ごみ箱に入らない場所 (ネットワーク) のときは確かめる。押しっぱなしは無視。同じ名前の説明の `.txt` も一緒に送る (同じ名前の別のファイルが残るときは残す)。消したあとは同じ位置 (= 次) を選び、結果はステータスバーに 1 行。使用中で消えないときは送り直し (最大 3 秒)、残ったら使っているアプリを添えて出す (ImageMimicArt と同じ処理、`recycle.py`)。
  - 採用している候補を消したら採用をやめ、`採用\` の番号のファイルと、次の「続き」のシーンの元画像も揃え直す (確かめるときは、採用中のものが入っていると書く)。
  - 作っている途中に消したものは、出来上がっても候補に戻さない。
  - 再生の窓 (候補のダブルクリック・通して再生) は、閉じたらプレーヤーから動画を外し、窓ごと片付ける。stop だけでは PrismLab が動画を開いたままで、再生した候補をごみ箱へ送れなかった (2026-11-15 利用者の指摘「採用以外を消そうとしても削除できない場合が多い」)。
- 「採用して次へ」: 選んだ候補を採用し、次のシーンへ (なければ「続き」で足す)。「採用だけ」/「採用をやめる」。採用すると、次のシーンが続きなら元画像を作り直し、採用のフォルダを揃える。
- **「コマを選んで次へ...」** (ボタン / 候補の右クリック「このコマから次へ...」。2026-11-15 利用者の希望): 選んだ動画の候補をスライダーで見て (初めは最後のコマ)、好きなコマから次のシーンを始める。候補を採用し、次のシーン (なければ足す) の元画像をそのコマにして、次のシーンへ進む。
  - 途中のコマ: 次のシーンは「シーンチェンジ」の「前のシーンのコマ」。あとで採用を変えても、選んだコマのまま。
  - 最後のコマ: 「続き」と同じなので、次のシーンのつなぎを「続き」にする (採用が変わったら作り直す)。
  - 次のシーンに自分で選んだ元画像 (手元の画像・T2I・ほかの動画のコマ) が入っていたら、置き換えてよいか確かめる (候補は残る)。続きの最後のコマ・同じ動画のコマなら確かめない。次のシーンが候補を作っている途中なら直さない。
- 物語の候補は続きから受け取れないので、作っている途中で閉じようとしたら確かめる (閉じたら ComfyUI に中止を送る)。

### 通して再生

- 選んでいるシーンから先の採用した動画を、間をあけずに順に再生する (◀ 前 / 次 ▶ / 最初から)。
- 切れ目を目立たせない (2026-11-15 利用者の指摘。1 つのプレーヤーで終わってから読み込むと、172 ms 止まって黒いコマも出ていた):
  - プレーヤーを 2 つ交互に使う。再生中に次のクリップを裏で読み込み、始める位置で止めておく。
  - 「終わり」の合図は最後のコマから 100 ms ほど遅れるので待たない。最後のコマが出たら次を動かし始め、1 コマ分たったら (前のほうが空のコマを出した・次のほうが進んだら、すぐ) 画面を切り替える。切れ目はふつうのコマの間隔 (24 fps で約 42 ms) と同じになった (実際の採用動画で測定)。
  - 「続き」のシーン (前のシーンの採用の最後のコマから作ったもの、前のクリップを直前に流すとき) は、1 コマ目が前のクリップの最後のコマと同じ絵なので 2 コマ目から流す。ボタンで選んだときは 1 コマ目から。
- 「採用のフォルダを開く」(番号順のフォルダ)、「J-Rate で開く」(選んでいるシーンの候補のフォルダ)。

### バッチで作る (試し。2026-11-16 利用者の希望)

- 物語のタブの「**バッチに足す...**」で設定の窓: 物語の名前・作る場所・最初の画像・リファレンス (顔。なくてもよい)・プロンプト (「/」「／」か改行で区切る。**区切った数がカット数**)・ワークフロー (I2V だけ。ラストフレームを指定するものは除く)・長さ・ベースプロンプト・送る前に「英語に」「盛る (プリセット)」・本数 (1〜20)。前の設定を覚える (`%APPDATA%\PrismLab\story_batch.json`)。前の設定がない欄は、開いている物語 (作る場所・ワークフロー・元画像) から入れる。

- 失敗 (候補が出来ない・LLM の失敗・元画像が取れない) したら、その物語はそこで止めて次の本へ。終わったら「出来た物語 n 本」と途中で止まったもの (名前: 理由) を窓とステータスバーで知らせる。
- **待ち行列** (2026-11-17 利用者の希望。夜中に試作をまとめて作るため): 「**バッチに足す...**」の窓の「待ち行列に足す」で足す。動いているあいだも足せる。最初の画像は何枚でも並べられ、1 枚ごとに 1 件 (名前は `名前_画像の名前`。ほかの設定は同じ)。

  - J-Rate・PWC (生成結果の帯)・量産ラインの結果から、右クリックの「**物語: バッチに足す... (n 枚)**」(量産ラインは「物語のバッチに足す...」) で画像を送ると、PrismLab を前に出して設定の窓を開き、最初の画像に入れる (前の設定が入っている。利用者の決定)。窓を開いているあいだに送ったものは、同じ窓に足す。送る側は待たせない (受け取ってから窓を開く)。動画は入れない。
  - **量産ラインとは同時に動く** (2026-11-17 利用者の決定。初めは「量産ラインが終わるのを待つ」だったが、台の空きを分け合う形にした)。どちらも相手を待たない・止めない。物語のタブの候補づくり (手で) とも同時に動く (台は分け合う)。

  - 最初の画像を足したあとで動かした・消したときは、その件を「最初の画像が見つかりません」として 1 度だけ知らせて終える (残りの本も作らない)。最初の画像・リファレンスを写せなかった物語のフォルダは消す (空の物語を残さない)。台が決まっていなければ始めずに帯で知らせる。

  - 1 件終わるごとにステータスバー、待ち行列が空になったら「出来た物語 n 本 (バッチ k 件)」と件ごとのまとめ・作った場所を窓で知らせる。

## 5. ほかのアプリから送る (2026-11-16 利用者の希望)

画像を選ぶのは J-Rate、プロンプトを試行錯誤するのは PromptWordCrafter (PWC) のまま、選んだものを右クリックで PrismLab に送る。PrismLab にタブとして取り込むのはやめた (J-Rate は C# で取り込めない。PWC は GenCommon のアプリの決まりが 1 つの起動に 1 つしか持てず、生成の入口が 2 つになる)。

### 送り方

- 右クリックの **「PrismLab に送る ▸」**: 量産のレシピの一覧 (`%APPDATA%\PrismLab\recipes.json` を送る側が読む。PrismLab が動いていなくても出せる) と、物語に送る項目。
  - J-Rate (選んでいる画像。動画は送らない): レシピ / **物語: 新しいシーンにする (n 枚)** / **物語: バッチに足す... (n 枚)** (4 章「バッチで作る」) / 1 枚のときだけ **物語: 選んでいるシーンの 元画像に / リファレンス (顔) に / ラストフレームに**。
  - PWC (選んでいるテキスト): レシピ / 1 件のときだけ **物語: 選んでいるシーンの元のプロンプトに**。送る前に、編集中の本文を保存する (PrismLab はファイルを読むので)。
  - PWC の生成結果の帯 (選んでいる画像。動画は送らない): J-Rate と同じ項目。帯は新しい順なので、作った順に並べて送る。
- 受け渡し: PrismLab の 2 重起動を止めるパイプ (`\\.\pipe\PrismLab-(ユーザー名)`) に JSON を 1 行 (改行で終わる) 書き、PrismLab が読み終えて切るまで待つ (送る側が先に切ると、読まれずに落ちることがある。2026-11-16 のテストで分かった)。PrismLab は改行まで読んだら処理して切る。改行のないもの (2 重起動の `show`) は、切られたときに読む。PrismLab が動いていなければ、JSON を一時フォルダに書いて `PrismLab.exe --send (JSON のパス)` で起動する (PrismLab.exe はデスクトップの `Application`、なければ `AI_projects\PrismLab\dist`)。
  - JSON: `{"cmd": "send", "from": "J-Rate", "target": "recipe", "recipe": "★から動画", "index": 0, "files": [...]}` / `{"cmd": "send", "from": "J-Rate", "target": "story", "slot": "scenes" | "source" | "reference" | "last" | "original" | "batch", "files": [...]}`。レシピは `index` の名前が `recipe` と同じならそれ、違えば同じ名前の最初のもの (送るまでに並べ替えたとき)。
  - それまでの `show` (2 つ目を起動したときに前に出す) はそのまま。`PrismLab.exe --send` で起動したものが 2 つ目だったときは、JSON を動いているほうに渡して終わる。
  - 送る側: J-Rate は `PrismLabLink.cs`、PromptWordCrafter は `prismlab_link.py`。テストは `tests\test_send.py` (PrismLab が受ける側。別のプロセスから送るものも)。
- 受け取ったら PrismLab を前に出し、そのタブ (量産ライン / 物語) に切り替えて、何を入れたかをステータスバーに出す。入れられないとき (量産が動いている・物語を開いていない・そのシーンが候補を作っている・レシピが見つからない・ファイルがない) は理由を窓で出し、何も変えない。
- 送ったあとは入口に入れて前に出すだけ (始めない。利用者の決定)。

### 量産の入口「選んだもの」

- 送るとそのレシピに切り替え、入口の種類を **[選択]** (選んだもの) にする (入口の切り替えの 4 つ目。選んだものがあるときだけ出す)。前のフォルダ・1 枚の画像などの設定は残るので、[フォルダ] などを押せば戻る (一時的に使う。利用者の決定)。入口の「× 外す」で選んだものを消し、前の入口に戻る。
- 選んだものはレシピに保存する (`picked`・`picked_from`。次に起動しても残る)。もう一度送ると置き換える (足さない)。
- 画像 (J-Rate) なら [フォルダ] と、`.txt` (PWC) なら [テキスト] と同じ扱い: ★の絞り込みはしない (人が選んだので)。回数は効く。★の引き継ぎは画像のときだけ。テキストなら最初の生成は T2I / T2V。
- 入口の札に「J-Rate から 12 枚」(テキストは「PromptWordCrafter から 3 件」) と先頭の 3 枚 (テキストは先頭の文)。消した・動かしたファイルは数えず、「見つからない 2」と添える。
- 出力の既定は `(先頭のファイルのフォルダ)\(レシピ名)`。試す 1 枚はサムネールのクリック・ドラッグ、なければ先頭。

### 物語に送る

- **新しいシーンにする**: 開いている物語の最後に、1 枚ずつ「シーンチェンジ・手元の画像」のシーンを足す (生成の設定は前のシーンを引き継ぐ)。最後に足したシーンを選ぶ。
- **元画像に / リファレンス (顔) に / ラストフレームに**: 選んでいるシーンのその欄に入れる (手元の画像を選んだのと同じ。元画像なら「続き」は「シーンチェンジ」になる)。
- **元のプロンプトに** (PWC): 選んでいるシーンの元のプロンプトをテキストの中身で置き換える (欄の編集として入れるので Ctrl+Z で戻せる。入れる前の文は履歴にも残す)。
- 送り先はいつも開いている物語 (利用者の決定)。開いていなければ知らせる。
- **絵コンテへのドロップ**: 画像 (J-Rate・エクスプローラーから。何枚でも) をシーンのカードに落とすとそのシーンのあとに、カードのないところ・「＋ シーン」に落とすと最後に、1 枚ずつシーンチェンジのシーンを足す。元画像の欄へのドロップは今までどおり (選んでいるシーンの元画像)。
- **量産ラインの結果から**: 「結果」は Ctrl・Shift で複数選べる。右クリック「物語の最後にシーンとして足す (n 枚)」で、選んだ画像 (動画・失敗は除く) を作った順に、新しいシーンにするのと同じ形で開いている物語の最後に足す。続けて足せるようにタブは量産ラインのまま、ステータスバーで知らせる。物語を開いていなければ知らせる。「物語のバッチに足す... (n 枚)」で、選んだ画像をバッチの最初の画像にする (4 章「バッチで作る」)。ほかに「開く」「エクスプローラーで表示」。
- **「J-Rate で選ぶ」**ボタン (物語の上の列): 前に元画像・リファレンス・ラストフレームを選んだフォルダ (`%APPDATA%\PrismLab\story_pick_folder.txt`。ファイルを選ぶ・ドロップ・送られたときに覚える) を J-Rate で開く。選んで右クリックで送り返す。覚えたフォルダがなければ J-Rate をそのまま開く。

### PWC の生成結果の帯に PrismLab の結果を出す

- PrismLab の記録 (`comfy_history.txt`) の量産・試作の行に、`origin` (入口のファイル。どのステップの出力でも同じ)、`originText` (入口がテキストのとき、始めたときの中身)、`recipe` (レシピ名)、`step` (何番目のステップか。1 から) を足す (GenCommon の `GenRequest`)。
